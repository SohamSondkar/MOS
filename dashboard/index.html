🏛️ Dual-Mode Architecture & System Philosophy Hardware / OS Boundary

The Multiprogramming Operating System (MOS) project simulates a complete computing machine and operating system kernel written in C. It enforces strict hardware-level separation between unprivileged user code and privileged kernel services:

Slave Mode (User Mode / CPU Execution)

The simulated CPU executes instructions (LR, SR, CR, BT, GD, PD, H). It has no direct access to real I/O devices or the page frame allocator. Any I/O request, illegal operation, invalid operand, page fault, or time limit expiration triggers a hardware interrupt and immediately traps to Master Mode.

Master Mode (Kernel Mode / MOS Supervisor)

The simulated kernel inspects the interrupt registers (SI, PI, TI). It dynamically allocates physical frames on valid page faults, executes card reading (READ) and line printing (WRITE), enforces CPU time (TTL) and line limits (TLL), and formats exact 6-line termination status blocks.

🔹 Phase 1 — Contiguous Linear Memory Phase 1
  • Flat 100-word physical memory (M[100][4], 400 bytes).
  • Direct physical addressing from location 00 to 99.
  • Service Interrupts only: SI = 1 (GD), 2 (PD), 3 (H).
  • Control cards: $AMJ, $DTA, $END.
  • Preserved in phase1/ and committed to git branch master.
  • Result: 11 / 11 test jobs passing against output_Phase1.docx.
🔷 Phase 2 — Paged Virtual Memory & Interrupts Phase 2
  • 300-word physical memory (M[300][4], 30 frames × 10 words).
  • 10-word Page Table in physical memory pointed to by PTR.
  • Random frame allocation (ALLOCATE()) with collision avoidance.
  • Multi-vector interrupts: SI (1..3), PI (1..3), and TI (2).
  • Process Control Block (PCB): TTL, TLL, TTC, LLC.
  • Result: 10 / 10 jobs passing, exact 1,500/1,500 byte match.

🔹 Phase 1 Architecture & Specifications Baseline Specification: AOSPROJECT1.pdf

Phase 1 models a single-job batch operating system with flat contiguous memory, direct addressing, and service interrupt handling.

Hardware Registers & Components:

  • M[100][4]: 100 memory words, each 4 bytes (total 400 bytes). Organized as 10 blocks of 10 words.
  • IR[4]: Instruction Register (2 bytes opcode, 2 bytes operand address).
  • IC: Instruction Counter (2 digits: 00 to 99).
  • R[4]: General Purpose Register (4 bytes).
  • C: 1-byte Comparison Toggle (1 = True, 0 = False).
  • SI: Service Interrupt flag (1 = Read/GD, 2 = Write/PD, 3 = Terminate/H).

Supervisor Services & Control Cards:

  • $AMJ: Start of job card. Invokes INIT() to clear memory and registers.
  • $DTA: Data card marker. Invokes MOS_STARTEXECUTION() to reset IC = 0.
  • $END: End of job card. Terminates execution and readies loader for next job.
  • READ(): Reads 40-character card into memory block address..address+9.
  • WRITE(): Writes 40-character memory block to printer output.
  • TERMINATE(): Emits 3 blank lines between jobs in output.

Debugged Challenge: Out-of-Data Card Skipping Bug

Problem: When Job 1 encountered an out-of-data condition (reading $END on GD), TERMINATE() contained a card-reading loop looking for $END. Because $END had already been consumed by READ(), TERMINATE() inadvertently read past the next job's $AMJ card, completely skipping Job 2.
Fix: Removed the card-reading loop from TERMINATE(). LOAD()'s outer loop naturally synchronizes to the next $AMJ, guaranteeing independent job isolation.

🔷 Phase 2 Architecture & Specifications Specification: AOSPROJECT2.pdf

Phase 2 introduces paged virtual memory, dynamic frame allocation, multi-vector interrupts, resource limits (time & lines), and error handling.

Paging & Physical Memory Model:

  • M[300][4]: Physical memory of 300 words (1,200 bytes) divided into 30 frames (0 to 29) of 10 words (40 bytes) each.
  • PTR: Page Table Register holds the physical word index of the Page Table (PTR = pt_frame * 10).
  • Page Table: 10 words in physical memory mapping virtual pages 0–9. Initialized with '****'.
  • ALLOCATE(): Randomly picks free frames (0..29) with collision resolution and tracking.
  • ADDRESSMAP(VA, &RA): Translates 2-digit virtual address VA to physical word address RA; detects PI = 2 (Operand Error) and PI = 3 (Page Fault).

Process Control Block (PCB) & Limits:

  • job_id: Parsed from $AMJ columns 5–8.
  • ttl: Total Time Limit (columns 9–12).
  • tll: Total Line Limit (columns 13–16).
  • ttc: Total Time Counter (incremented each CPU cycle in Slave Mode).
  • llc: Line Limit Counter (incremented in WRITE(); terminates on LLC > TLL).
  • Valid vs Invalid Page Fault: Faults on GD / SR dynamically allocate frames; faults on LR, CR, BT, PD terminate with EM = 6.

🔄 Address Translation Flow (MMU)

When the CPU accesses virtual address VA (e.g. IR[2..3] or IC):

  1. ADDRESSMAP() checks if characters are valid decimal digits. If not → PI = 2 (Operand Error).
  2. Computes virtual page p = VA / 10 and word offset d = VA % 10.
  3. Reads page table entry M[PTR + p]. If unallocated ('*') → PI = 3 (Page Fault).
  4. Reads real frame number f from entry. Computes physical address RA = f * 10 + d.
⚡ Interrupt Arbitration & Trap Handling

At the conclusion of each instruction cycle:

  1. current_pcb.ttc increments by 1. If TTC == TTL, hardware sets TI = 2.
  2. If SI != 0, PI != 0, or TI != 0, CPU breaks user loop and calls MOS().
  3. Master Mode evaluates the 2D matrix: dispatching READ, WRITE, dynamic allocation, or TERMINATE(EM).
